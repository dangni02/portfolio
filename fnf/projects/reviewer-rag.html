Key Projects 03

>>>Reviewer-RAG 검색 검증 파이프라인

RAG 검색 결과에 섞이는 무관 문서로 인한 답변 오류를 줄이기 위해 약 8,000개 문장 벡터 DB와 Reviewer 검증 단계를 구축하여 정확도 약 3% 개선

+3%기존 RAG 대비 정확도

Architecture

전체적인 아키텍처

약 8,000개 문장을 sentence chunk로 분할·임베딩해 저장하고, 검색과 답변 생성 사이에 Reviewer 검증 단계를 추가. FEVER 데이터셋으로 검증.

Problem

문제 원인

  • 검색 결과에 질문과 관계없는 문장이 포함됨
  • 이름이나 단어가 유사한 문서를 관련 문서로 잘못 검색하는 경우가 있었음
  • 기존 파이프라인은 검색된 문서의 관련성을 다시 확인하지 않았음
  • 검색 결과가 그대로 답변 생성에 사용되면서 오류로 이어졌음

Process

해결 과정

  • 약 8,000개 문장을 sentence chunk로 분리하고 임베딩으로 변환
  • PostgreSQL + pgvector 기반 검색 DB를 구축
  • 검색된 문서를 Reviewer가 먼저 확인하도록 파이프라인에 검증 단계를 추가
  • 관련성이 낮은 문서를 제외한 뒤 Answerer에 전달
  • 테스트
    • FEVER 데이터셋으로 기존 RAG와 Reviewer-RAG를 동일한 조건에서 비교
    • 검색 문서의 관련성과 최종 답변 정확도를 측정하고 오류 사례로 필터링 결과를 확인

Result

결과

  • 약 8,000개 문장을 검색 가능한 형태로 구축
  • 데이터 검색과 답변 생성 사이에 검증 단계를 추가
  • 기존 RAG 대비 정확도 약 3% 향상
  • 이름은 유사하지만 주장과 무관한 문서를 일부 제거
